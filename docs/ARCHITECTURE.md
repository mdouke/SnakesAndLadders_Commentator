# 全体構成・設計方針

## 1. システム境界

本システムが正とするのは、物理盤面ではなくコンピュータ上のゲーム状態です。カメラはサイコロだけを認識し、物理コマや盤面は認識しません。

```text
カメラ ──> サイコロ認識 ──> 出目の確定 ──> ゲームエンジン
                         │                    │
                         │                    ├──> イベント・統計・スナップショット
                         │                    ├──> LLM実況 ──> 表示 ──> TTS
                         │                    └──> 管理者UI / プレイヤーUI
                         └──> 管理者による確認・手動入力

DJI Mic Mini ──> 録音サービス ──> MP4 + ゲーム時刻との同期情報
```

管理者 UI とプレイヤー UI は同じバックエンドへ接続します。状態更新は API で行い、進行状態・認識結果・コメントは WebSocket で配信します。

## 3. モジュール責務

### ゲームエンジン

ゲームエンジンはカメラ、DB、LLM、UIに依存しない純粋なドメインロジックにします。同じ入力と直前状態から必ず同じ結果を返すことで、訂正・再計算・復元を安全にします。

1ターンは次の値を明示的に保存します。

- 移動前位置
- 確定出目
- 通常移動後位置
- ヘビ・ハシゴ適用後の最終位置
- 超過フラグ
- 発生イベント
- 適用前後の状態バージョン

100を超える場合は通常移動後位置と最終位置を移動前位置と同じにし、出目と超過イベントだけを履歴へ残します。

### 履歴、訂正、復元

データは「上書き」ではなく追記を基本にします。

- `event`: 起きた操作と結果。訂正前のものも残す
- `turn`: 現在有効なターン系列と、無効化された版
- `snapshot`: 毎ターン終了時の復元可能なゲーム状態
- `correction`: 対象、理由、操作者、訂正前後の値

Undo は対象以降のイベントを無効化して直前スナップショットを復元し、Redo は無効化した系列を再適用します。過去状態から新しく進行した場合は履歴を削除せず、新しいブランチとして記録します。

サイコロ訂正は、訂正対象ターン直前の状態から有効な後続ターンを順に再計算します。位置の手動訂正は専用イベントとして記録し、それ以降を同じ方法で再計算します。

### サイコロ認識

既存 `dice_recognize/dice_detector.py` の単フレーム検出を核として、次を追加します。

- カメラ選択、接続監視、再接続
- ROI設定と保存
- フレーム単位の値・信頼度
- 動き量による静止判定
- 同じ値がNフレーム継続した場合の候補確定
- 自動確定しきい値と管理者確認しきい値
- 一度確定したサイコロがROIから除去／再移動されるまでのロック
- 認識不能時のタイムアウトと手動入力

検出結果とゲームへの確定入力を分離し、カメラの誤検出だけでゲーム状態を更新しない設計にします。

### LLM実況とTTS

Claude/OpenAIは共通の `CommentaryProvider` インターフェースで扱います。プロンプトには構造化したターン状況を渡し、要求ごとに次を記録します。

- game ID / turn ID / request ID
- プロンプトの版と全文
- provider / model
- 開始・終了時刻、所要時間
- 応答全文、エラー、再試行回数

生成要求にはゲーム状態の世代番号を付けます。応答時に現在の世代・ターンと一致しなければ保存のみ行い、画面表示と読み上げはしません。訂正・Undo・ゲーム終了時には待機中のTTSもキャンセルします。

APIキーは環境変数またはOSの秘密情報ストアから取得し、DB・ログ・フロントエンドへ出しません。

### 録音

録音はゲーム進行から独立させ、失敗してもゲームを続行できるようにします。録音ファイルにはゲームIDを付け、録音開始時の単調増加時計とゲームイベント時刻の対応を保存します。

音声のみのMP4かカメラ映像込みMP4かが未決定のため、入力ソースと出力プロファイルを差し替え可能にします。DJI Mic Mini の2チャンネルがOSからどの形式で見えるかは対象機で事前検証します。

## 4. 主要データモデル（暫定）

| 集約 / テーブル | 主な内容 |
|---|---|
| `games` | ゲーム状態、現在手番、状態世代、開始・終了時刻 |
| `players` | 名前、表示名、読み方、色、手番順 |
| `board_configs` | ゴール、マス配置、ヘビ、ハシゴ、版 |
| `turns` | 出目、各位置、超過、手番、状態、履歴ブランチ |
| `events` | 種別、payload、時刻、有効/無効、因果関係 |
| `snapshots` | ターン終了時の復元用状態 |
| `corrections` | 訂正種別、理由、変更前後、操作者 |
| `dice_observations` | カメラ値、信頼度、確定値、手動入力情報 |
| `commentary_requests` | プロンプト、応答、モデル、時間、状態世代 |
| `tts_jobs` | 読み上げ内容、音声設定、開始・終了・取消状態 |
| `recordings` | デバイス、チャンネル、ファイル、同期、エラー |

統計はまずイベントから再計算可能にし、性能上必要になった時点でキャッシュを追加します。これにより訂正後の整合性を保ちます。

## 5. 盤面設定形式（案）

```json
{
  "schemaVersion": 1,
  "id": "standard-01",
  "name": "標準盤面 01",
  "goal": 100,
  "jumps": [
    { "type": "ladder", "from": 4, "to": 14 },
    { "type": "snake", "from": 98, "to": 79 }
  ],
  "layout": {
    "type": "serpentine",
    "columns": 10,
    "rows": 10,
    "startCorner": "bottom-left"
  }
}
```

保存時には、範囲外、同一開始マスの重複、向きが逆のヘビ／ハシゴ、循環するジャンプを検証します。盤面レイアウトはUI描画用で、ゲームルールとは分離します。

## 6. 状態遷移

```text
SETUP -> READY -> WAITING_FOR_ROLL -> RECOGNIZING
                       ^                   |
                       |                   v
                       +---- TURN_DONE <- CONFIRMING <- low confidence
                                         |
                                         +---------- auto/manual confirm

任意の進行状態 -> PAUSED -> 直前の進行状態
任意の進行状態 -> ERROR（復旧可能）
GOAL -> FINISHED（終了条件の設定に従う）
```

プレイヤー画面の「待機中／認識中／生成中／読み上げ中／一時停止中」は、このゲーム状態と実況ジョブ状態から決定します。

## 7. テスト方針

- ドメイン単体テスト: 100ぴったり、超過、ヘビ、ハシゴ、順位、統計、最短手数
- プロパティテスト: 位置が常に0〜100、超過時不変、履歴再生の決定性
- 認識テスト: 保存映像・画像による再現可能な評価、連続確定、重複防止
- 結合テスト: DB保存・復元、LLM/TTSのフェイク、WebSocket配信
- E2E: 設定→複数ターン→訂正→Undo/Redo→復元→終了
- 実機テスト: カメラ切断、DJI Mic Mini 2ch、長時間稼働、ネットワーク断

外部APIとハードウェアを使わずに主要テストを実行できるよう、カメラ映像・LLM・TTS・録音にはフェイク実装を用意します。

## 8. 実装前に確定する事項

次は要件から一意に決められないため、初期実装の早い段階で決定します。

1. 1人目のゴールでゲーム終了か、全員ゴールまで継続するか
2. 同位置の順位、ゴール済みプレイヤーの手番、複数ゴール時の順位規則
3. 「実際に位置が変化した累計マス数」を符号付き・絶対値・前進のみのどれで数えるか
4. 位置の手動訂正を累計移動量・最大到達位置などの統計へ含めるか
5. ハシゴ／ヘビ移動後に別のヘビ／ハシゴを連続適用するか
6. コメント訂正時に旧コメントを画面から置換するか、訂正コメントとして追加するか
7. TTSエンジンと利用可能な日本語音声
8. 録音を音声のみMP4にするか、カメラ映像込みMP4にするか
9. 対象OS、カメラ台数、管理者画面とプレイヤー画面を同一PCで表示するか
10. ログ・録音の保存期間と個人情報の取り扱い

## 9. 初期版に含めないもの

- 物理盤面・物理コマの画像認識
- 勝率計算
- 盤面やサイコロのアニメーション
- 高度な演出
- 複数端末・遠隔環境を前提にした認証基盤（必要になれば追加）
