# ADR 0005: LLM実況と読み上げ

- 状態: Accepted
- 決定日: 2026-11-18

## 背景

Phase 6 では、確定したターンだけを実況し、訂正・遅延・API障害があっても誤った文を表示したり
読み上げたりしないことが完了条件である。ClaudeとOpenAIを切り替えられること、要求ごとの記録、
コメントの再生成、不適切な応答の扱い、macOS標準音声による読み上げを決める必要があった。

## 決定

### Provider

- `services/llm/providers.py` の `CommentaryProvider` を共通の境界にする。実装は
  `fake`（テンプレート）、`claude`（Anthropic公式SDK）、`openai`（OpenAI公式SDK・Responses API）。
- 既定の Provider は `fake`。APIキーなしでも動き、管理画面で切り替える。
- 既定モデルは Claude が `claude-opus-5-5`、OpenAI が `gpt-5-mini`。どちらも管理画面で変更できる。
- Claude は応答を速くするため `effort: low` で呼ぶ。対応モデルでは、安全分類器で断られたときに
  サーバー側で別モデルへ切り替える `fallbacks: "default"`（beta `server-side-fallback-2026-07-01`）
  を付ける。それでも断られた場合（`stop_reason: refusal`）は代替文にする。
- APIキーは環境変数（`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`）または SDK の認証情報から読む。
  本番起動時は `var/secrets.env`（Git管理外、`COMMENTATOR_SECRETS_PATH` で変更可）を一度だけ読み、
  まだ設定されていない環境変数として登録する。ターミナルの `export` が優先される。
  ファイルが自分以外から読める権限なら警告する。キーの値は DB、ログ、画面には出さず、
  ログには読み込んだ変数名だけを残す。設定APIはキーの項目を受け付けない（422）。

### タイムアウトと再試行

- タイムアウト（1〜60秒、既定10秒）と再試行回数（0〜3回、既定1回）は管理画面で設定する。
- SDK の自動再試行は切り、サービスが一か所で再試行する。再試行するのはタイムアウト、接続失敗、
  429、5xx だけで、待ち時間は 0.5秒・1秒・2秒と倍にする。認証エラーや断りは再試行しない。
- 新しいターンや再生成で要求が古くなったら、残りの再試行はしない。

### 古い応答の抑止

- 要求ごとに `requestId` を発行し、表示してよい要求は常に1つ（最新ターンの最新要求）だけにする。
- 生成が終わった時点で最新の要求でなければ、記録だけ残して表示しない（`discarded`）。
- 読み上げは、話し始める直前にもう一度「今の要求か」を確かめる。実況が変わったら、
  話している途中でも止め、古い文を待ち行列に残さない。
- ゲームを中止・保存終了したときは実況を消し、読み上げも止める。中止の取り消しや再開では、
  前のコメントを繰り返さない。

### 不適切・空・長すぎる応答

すべての応答は表示前に `services/llm/safety.py` で確認する。

| 応答 | 扱い |
|---|---|
| 空・空白だけ | テンプレートの代替文 |
| 禁止語を含む | テンプレートの代替文 |
| 上限を超える | 上限内の最後の文末で切る。文末がなければ代替文 |
| 途中で切れた（`max_tokens` など） | 代替文 |
| Markdown・かぎかっこ・改行 | 取り除く（読み上げのため） |
| 失敗・タイムアウト・断り | 代替文 |

代替文は、ゲームエンジンが計算した出目・位置・ヘビ／ハシゴ・ゴールだけから作るテンプレートの文で、
事実と食い違うことがない。画面には `source: fallback` と理由を出し、管理者に分かるようにする。

長さの目安と上限（日本語は文字数、英語は単語数）:

| 長さ | 日本語 | 英語 |
|---|---|---|
| 短い | 40字（上限70字） | 20語（上限35語） |
| ふつう | 80字（上限130字） | 40語（上限65語） |
| 長い | 140字（上限210字） | 70語（上限105語） |

### コメントの訂正（再生成）

- 管理者は最新ターンの実況を再生成できる。表示中のコメントは記録に `superseded` として残し、
  画面はすぐ「準備中」にしてから新しい版に置き換える。古い版は表示も読み上げもしない。
- 出目の訂正で最新ターンが変わったとき、Undo で最新ターンが消えたときも、表示中だったコメントは
  `superseded` になる。

### 記録

`commentary_requests` テーブル（ゲームと同じ SQLite ファイル）に、1要求1行で次を保存する。
ゲームID、ターンID、状態世代、再生成の回数、Provider、モデル、プロンプトの版と全文、応答全文、
最終的に表示した文、代替文の理由、試行回数、エラーの一覧、Provider の request ID、開始・終了時刻、所要時間、
画面での結果（`pending`・`displayed`・`discarded`・`superseded`）。
管理画面の「実況の記録」と `GET /api/commentary/requests` で確認できる。

### 読み上げ

- `say` で一時ファイルに音声を作り、`afplay` で音量をつけて再生する。どの音声でも音量が効き、
  どちらの段階でも止められる。代わりに、話し始めまで約1秒かかる（Phase 8 で再評価する）。
- 2026-11-22: 実験は macOS の音声で行うことにしたため、Google と同じく文ごとに音声を作り、1文目からすぐ再生する。
  `say` は1文を作るのに約1.7〜1.9秒かかり、短い文の再生時間より長いので、2文先まで並行して作る。
  測定（この Mac、速さ230、4文の実況）: 話し始めまで約1.9秒（全文を一度に作ると約2.9秒、以前の測定では7〜10秒）、
  文と文の間の隙間は約0.02秒。
- 音声、速さ（`say` の1分あたりの語数、80〜400、未指定は音声の標準）、音量（0〜1）を設定でき、
  試聴できる。声の高さは標準の音声では扱わない（ARCHITECTURE の方針どおり Phase 8 で判断）。
- プレイヤー名の読み方は、表示名を読み方に置き換えてから読み上げる（長い名前から順に置換）。
- 本番以外（テスト、`create_app()` の既定）は音を出さない `SilentTtsEngine` を使う。
- 読み上げ内容は専用テーブルではなく、構造化ログ（`speech_finished`・`speech_cancelled`・
  `speech_failed`）に残す。

## 結果

- APIキーがなくても、またAPIが落ちても、事実に沿った代替文で進行できる。
- 古い実況は、表示側（要求IDの照合）と読み上げ側（話す直前の照合と途中停止）の二重に止まる。
- 実際の Claude / OpenAI の文の質と遅さは、キーを設定した実機で確認する必要がある。
- 外部の音声生成API（P2）は `TtsEngine` を実装すれば追加できる。

## 追記（2026-11-19）: Google Cloud Text-to-Speech

macOS の標準音声は、実況1つ分（約60文字）を音声ファイルにするのに7〜10秒かかり、表示から読み上げまでが
遅かった。そこで外部の読み上げとして Google Cloud Text-to-Speech を追加した（料金が安く、WaveNet・Standard
は毎月400万文字まで無料）。

- 読み上げの方法 `provider`（`macos` / `google`）を設定で切り替える。Google の音声名と速さ（0.5〜2.0倍）も設定する。
- 認証は APIキー（`GOOGLE_TTS_API_KEY`、`var/secrets.env`）。キーはヘッダーで送り、画面・ログ・設定には出さない。
- 文を「。」「！」「？」で区切り、1文目を作ったらすぐ再生し、再生中に次の文を作る。同じ文は覚えておいて再利用する。
- 再生は macOS と同じく `afplay`（音量設定と途中停止がそのまま使える）。
- Google が失敗した時（ネットワーク、キー、上限）は、その実況を macOS の音声で読む。

### Gemini TTS（2026-11-19 追加）

読み方を文章で指示できる Gemini TTS を、読み上げの方法 `gemini` として追加した。

- Gemini API（Google AI Studio の APIキー `GEMINI_API_KEY`）の `v1beta/interactions` に、文と
  `speech_metadata.style`（読み方の指示）を送り、WAV を受け取る。モデルは `gemini-3.8-flash-tts`
  （軽量版 `gemini-3.8-flash-lite-tts`）、声は Kore など30種類。
- 文ごとの分割・先読み・キャッシュ・`afplay` での再生・失敗時の macOS への切り替えは Google と同じ。
- Cloud Text-to-Speech 経由の Gemini-TTS（`model_name` 指定）も試したが、Vertex AI の権限確認のため
  OAuth の資格情報が必要で、APIキー（サービスアカウントに紐づけたキーも含む）は受け付けられなかった。
- 無料枠は回数の上限が小さく、送った文がサービス改善に使われる場合がある。ユーザースタディでは有料枠で使う。

#### 接続先の追加と切り替え（2026-11-19）

Gemini API は有料枠でも `gemini-3.8-flash-tts` が1日100回までで、ゲームに足りなかった。そこで
Gemini の接続先 `geminiBackend` を追加した。

- `cloud`（既定）: Cloud Text-to-Speech の `text:synthesize` に `input.prompt` と `voice.model_name`
  （`gemini-2.5-flash-tts` など）を付けて呼ぶ。認証はサービスアカウントの鍵ファイル
  （`GOOGLE_APPLICATION_CREDENTIALS`、`var/` に置く）から google-auth で取る OAuth トークン。
  サービスアカウントにはロール「Agent Platform ユーザー」（`roles/aiplatform.user`）が必要。
  既定の上限は1分150回で、1日の上限はない。
- `api`: Gemini API（`GEMINI_API_KEY`）。
- 失敗した時は Gemini → Google の標準の声 → macOS の順に試す。上限エラー（429）で Google が
  再試行までの時間を返した場合、その間はその読み上げ方法を飛ばす。
