# ADR 0001: 履歴ブランチとターンID

- 状態: Accepted
- 決定日: 2026-11-13

## 背景

出目や位置を訂正して後続状態を再計算するとき、訂正前の履歴を監査用に残しながら、現在有効な系列を一意に識別する必要がある。分岐前まで同一だったターンを別物として複製すると、実況・統計・外部参照との対応が失われる。

## 決定

- ゲーム作成時のブランチIDは `main` とする。
- ターンIDは UUID v5 で、`{game_id}/{branch_id}/turn/{turn_number}` から決定的に生成する。
- 訂正対象より前の操作・ターンは親ブランチのレコードをそのまま有効に保ち、ターンIDも引き継ぐ。
- 訂正対象と後続操作は新しいブランチIDで再生し、新しいターンIDを生成する。
- 訂正前の操作イベントとターンは削除せず、`active = false` にしてSQLiteへ残す。
- Undoは管理者操作単位で有効化・無効化したイベント集合を反転し、Redoは同じ集合を再適用する。詳細は [ADR 0002](0002-undo-redo-and-recovery.md) に記録する。
- Undo後に新しい操作を行うと新しいブランチIDを発行し、取り消したターンIDを再利用しない。
- すべての変更APIはクライアントが `expectedStateVersion` を送り、不一致なら409を返す。

## 永続化境界

`games`、`operation_events`、`turns`、`snapshots` の更新は一つのSQLiteトランザクションで行う。アプリケーションはRepositoryから取得したコピーを変更し、保存が成功した後にだけその状態を公開する。保存失敗時は変更前の永続状態を維持する。

## 結果

分岐前の参照は安定し、訂正後の系列は親系列と混同されない。履歴量は増えるが、監査・Undo/Redo・再計算・障害復元に必要な情報を失わない。
