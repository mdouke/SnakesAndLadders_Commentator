# サイコロ認識の実機確認

通常の自動テストは保存画像とフェイクカメラだけで実行する。この文書の操作はUSBカメラを接続したMacで、ユーザー立ち会いのもと実施する。

## 実施前

1. macOSの「プライバシーとセキュリティ > カメラ」で、使用するターミナルまたはアプリへカメラ権限を許可する。
2. USBカメラを接続し、他のアプリが使用していないことを確認する。
3. 黒く反射の少ない背景、白いサイコロ、影や映り込みの少ない照明を用意する。
4. `nvm use` でNode 22、`.venv` でPython 3.13の環境を選ぶ。

## 確認項目

- カメラを列挙し、対象デバイスIDを選択できる。
- 接続後にフレームを継続取得できる。
- ROIがサイコロを振る領域だけを含み、保存後の再起動でも同じ比率で復元される。
- 「振る → 静止 → 候補 → 一度だけ確定 → 除去待ち → 次を受付」の順に遷移する。
- 同じサイコロを置いたままにしても二度確定しない。
- サイコロの除去、または明確な再移動で次の受付へ進む。
- 低信頼度では自動確定せず、管理者が承認または1〜6へ修正できる。
- USBケーブルを抜くと切断状態になり、再接続後は待機状態から安全に再開する。
- 認識タイムアウト後に手動入力できる。

## ライブプレビューと収録

APIや管理画面とは独立した実機調整ツールを起動する。

```bash
.venv/bin/python -m commentator.tools.vision_bench
```

画面では、全体映像上のROI、ROI拡大、検出輪郭と目、赤色の却下候補、外形マスク、
目の計数パネル、
状態機械、候補値、信頼度の4内訳、動き量、実測FPS、直近の判断を確認できる。白しきい値、
目しきい値、ROI、解像度、対応カメラでは露出をその場で調整できる。露出は「自動露出」をオフにすると
`-13〜0` のスライダーで変更できる。値の解釈と対応範囲はカメラ機種に依存する。「設定保存」を押した場合だけ
`var/vision-settings.json` へ保存する。

自動確定しきい値、確認依頼しきい値、静止判定フレーム数、同値連続フレーム数もライブ調整できる。
フレーム数の横には、実測FPSから換算した待ち時間を表示する。認識中に変更した場合は現在の投擲をリセットせず、
次に待機または除去待ちへ入った時点で反映する。画面に「次の待機／除去待ちで反映」と出ている間は反映待ちである。

- `automaticThreshold` （既定0.83、0.50〜1.00）: この信頼度以上なら自動確定する。上げると誤確定は減るが、管理者確認が増える。
- `confirmationThreshold` （既定0.60、0.50〜1.00）: この信頼度以上で自動確定未満なら確認依頼に回す。自動確定しきい値より高くはできない。
- `stationaryFrames` （既定10、1〜15）: 静止と判定するまでの連続フレーム数。下げると早くなるが、転がり終わる前に判断する危険が増える。
- `consecutiveValueFrames` （既定3、1〜5）: 同じ出目が連続して必要なフレーム数。下げると早くなるが、一時的な読みを採用しやすくなる。
- `minPipSizeConsistency` （既定0.50、0.00〜1.00）: 採用した目が2個以上のときの「最小面積 ÷ 最大面積」の下限。
  これより小さい場合は、総合信頼度が高くても白飛びなどで一部の目を読み落とした可能性があるため確認依頼に回す。
  1の目は比較対象がないため1.00とする。ライブ画面の認識状態、目の計数パネル、録画イベントにも値を表示する。
- `maxSinglePipCenterOffset` （既定0.22、0.00〜0.50）: 1と読んだ目の中心からの距離を、補正面の一辺で割った値の上限。
  これを超える1は、2以上の目が白飛びで消え、角の目だけが残った可能性があるため確認依頼に回す。
  2〜6の出目には適用しない。

11/16の60投擲映像（外形230、目235）をフレーム時刻付きで再生した比較は次のとおり。

| 静止 / 同値フレーム | 正しい自動確定 | 誤自動確定 | 確認候補 | 区間外 | 投擲開始から自動確定までの中央値 |
|---|---:|---:|---:|---:|---:|
| 10 / 3 | 56 | 0 | 4 | 2 | 3.50秒 |
| 5 / 3 | 53 | 0 | 7 | 2 | 2.94秒 |
| 4 / 3 | 54 | 0 | 6 | 2 | 2.84秒 |
| 4 / 2 | 55 | 0 | 5 | 3 | 2.74秒 |
| 3 / 3 | 54 | 0 | 6 | 2 | 2.74秒 |

4フレーム前後で約0.6秒短縮したが、最終値は明るさ、角度、背景を変えた実機投擲で決める。

### 2種類のマスク

「外形マスク（白しきい値）」は、白いサイコロの外形を背景から分離するために使う。白しきい値
の右には「設定値 / 適用値」を表示し、固定時は両方が一致することを確認する。自動時の適用値は、
そのフレームで外形抽出用の大津法が選んだ値である。外形が変わらない範囲では、白しきい値を
動かしても出目が変わらない場合がある。

「目の計数（補正後）」は、実際に出目を決めている処理を表示する。候補ごとに左へ180x180の
射影補正済みグレー面、右へ目の計数用マスクを並べる。見出しの `#1` はROI拡大の候補番号、
`pips=3` は採用した目の数、`PipThr=85 auto` はその面で自動決定した暗部しきい値を表す。

- 緑の輪郭: 目として採用
- 赤の `area<` / `area>`: 面積が範囲外
- 赤の `circ`: 凸包の円形度が不足
- 赤の `solid`: 暗い輪郭が欠けすぎている、または細い弧である
- 赤の `aspect`: 縦横比が大きすぎる

判定値が実物と違う場合は、このパネルで落ちた目の赤い理由と数値を確認する。外形マスクに
穴が見えても、目の計数パネルで赤く却下されていれば、その穴は出目に含まれない。

現在の実機条件では、外形しきい値の初期値を固定 `230`、目しきい値を固定 `235` とする。照明や
背景が変わった場合は `0〜255` のスライダーで調整する。目しきい値を上げると明るめの部分まで目候補に
含み、下げると暗い部分だけを目候補にする。上げすぎると影や側面を目として数え、下げすぎると
反射で薄くなった目を見失う。操作欄の「設定 / 適用」と計数パネルの `PipThr=... fixed` が
一致することを確認する。保存ボタンを押すと `pipThreshold` として設定へ保存され、保存映像の
評価にも同じ値が使われる。必要な場合は「白しきい値を自動」「目しきい値を自動」を有効にし、
フレームまたは面ごとの大津法へ切り替えられる。

「録画開始」を押すまでは映像や静止画を保存しない。録画中は全体映像ではなくROIだけを
`recordings/dice-evaluation/YYYYMMDD/` へ保存し、同じベース名で次のファイルを作る。

- `.avi`: ROI映像
- `.frames.jsonl`: フレーム番号、録画開始からの秒数、単調増加時刻
- `.events.jsonl`: 状態遷移、自動確定、確認候補、信頼度内訳
- `.labels.json`: 評価CLIが読み込める投擲区間と正解値
- `.settings.json`: 録画開始時のカメラ、ROI、画像しきい値、認識しきい値、待ちフレーム数、露出

投擲を始めて状態が「移動中」になった後、サイコロの実際の出目を画面の1〜6ボタンまたは
キーボードで入力する。入力は同じ投擲中なら上書きできる。録画停止時に未入力の投擲が
あれば件数を表示し、誤った正解値を推測してラベルへ入れることはしない。確認待ち候補は
イベントへ保存後に次の投擲を受け付けるため、収録周期は停止しない。

録画中は「投擲」「自動確定」「確認候補」「正解入力」「未入力」を画面右上に表示する。
正解入力はボタンを押した回数ではなく、正解値が入力済みの投擲数である。同じ投擲で入力を
訂正しても1件として数える。60投擲の終了時は、投擲60・正解入力60・未入力0を確認してから
録画を停止する。

## 記録する評価値

- 正解した投擲数 / 全投擲数（認識率）
- 誤った値を確定した数 / 確定数（誤確定率）
- 投擲開始から確定までの時間
- 照明、カメラ角度、距離、背景、使用したしきい値

映像や画像を通常ログへ含めない。評価用に保存する場合は、通常ログと分離した明示的な保存先を使い、参加者が映り込まない画角と研究計画に沿った削除・アクセス管理を確認する。

## 保存映像の評価

映像と同じ時間軸の正解ラベルをJSONで用意する。時刻は秒で、投擲区間同士を重複させない。

```json
{
  "rolls": [
    {
      "id": "roll-001",
      "expectedValue": 4,
      "startSeconds": 1.2,
      "endSeconds": 3.8
    }
  ]
}
```

次のコマンドで評価し、標準出力または `--output` でJSONレポートを得る。

```bash
.venv/bin/python -m commentator.services.vision.evaluation \
  study-video.mp4 study-video.labels.json \
  --settings var/vision-settings.json \
  --frame-times study-video.frames.jsonl \
  --roi-cropped \
  --config var/recognition-config.json \
  --output var/evaluations/study-video.report.json
```

`--settings`と`--config`は省略できる。`--settings`は保存済みのROI、画像しきい値に加え、上の6つの認識条件も適用する。
`--config`を同時に指定した場合は、従来どおり`--config`の認識条件を優先する。省略したキーには既定値を使う。
`--frame-times` にライブプレビューの `.frames.jsonl` を指定すると、AVIの固定FPSではなく収録時の実時刻を使う。
フレーム番号が連続しない場合、時刻が後戻りする場合、映像と時刻の件数が違う場合はエラーにする。
ライブツールの `.avi` はすでにROIだけを保存しているため、その `.settings.json` を使うときは `--roi-cropped` も指定し、
保存済みROIを二重に切り出さないようにする。

```json
{
  "movementThreshold": 0.08,
  "stationaryThreshold": 0.02,
  "stationaryFrames": 10,
  "consecutiveValueFrames": 3,
  "candidateWindowFrames": 5,
  "removalFrames": 3,
  "automaticThreshold": 0.83,
  "confirmationThreshold": 0.60,
  "recognitionTimeoutSeconds": 10.0,
  "minPipSizeConsistency": 0.50,
  "maxSinglePipCenterOffset": 0.22,
  "maxPipLayoutError": 0.15
}
```

レポートには次を含む。

- 最初の判断が正しい自動確定または確認候補だった投擲の割合（認識率）
- 誤った自動確定と投擲区間外の自動確定の割合（誤確定率）
- 投擲開始から最初の正しい判断までの平均・中央値・95パーセンタイル
- 投擲ごとの最初の判断、正誤、確認待ちの有無、確定時間
- しきい値未満で破棄した候補と、その信頼度内訳
- 判断ごとの総合信頼度、4つの従来内訳、目サイズの均一性
- 認識設定、ROI、FPS、総フレーム数、映像時間、評価日時（UTC）

評価ツールは映像を読み取るだけで、映像やフレームを通常ログまたはレポートへ埋め込まない。

## 初回実機評価の条件

- 所要時間: 45〜60分
- 投擲回数: 最初に接続・ROI・切断復旧を確認した後、評価用に60回。各面が極端に少ない場合は、各面が最低5回になるまで追加する。
- 保存先: `recordings/dice-evaluation/YYYYMMDD/`。このディレクトリはGit管理対象外である。
- 画角: サイコロと黒い背景だけを基本とし、顔、名札、画面、書類などの個人情報を映さない。手が入る条件は重複防止と除去判定の確認に必要な範囲だけにする。
- 正解ラベル: 各投擲の開始・終了時刻と実際の出目を、映像と同じ時間軸で記録する。

## 2026-11-17 静止したサイコロの重複自動確定

`vision-bench-20261117-111202` で、ROI右下に静止した出目3が107.8秒から130.3秒までに
9回自動確定された。最初の1回を除く8回は同じサイコロの重複確定である。

原因は次の2点が重なったことだった。

- 従来の四隅の並べ替えは `x+y` と `y-x` の最小・最大で選んでいた。正方形が45°のときに同値の隅ができ、
  同じ点を2回選ぶことがあった。射影補正後の面が灰色に潰れ、出目3と `pip_count_0` の却下がフレームごとに揺れていた。
- 除去待ちは却下候補を「サイコロなし」と数える一方、待機は却下候補を「サイコロあり」と数えていた。
  そのため、却下3フレームで待機へ戻り、動いていない同じサイコロで新しい認識周期を始めていた。

四隅は中心からの角度で時計回りに並べ、`x+y` が最小の点から始めるように変更した。除去待ちでは
