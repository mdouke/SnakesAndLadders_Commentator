# サイコロ認識の実機確認

通常の自動テストは保存画像とフェイクカメラだけで実行する。この文書の操作はUSBカメラを接続したMacで、ユーザー立ち会いのもと実施する。

## 実施前

1. macOSの「プライバシーとセキュリティ > カメラ」で、使用するターミナルまたはアプリへカメラ権限を許可する。
2. USBカメラを接続し、他のアプリが使用していないことを確認する。
3. 黒く反射の少ない背景、白いサイコロ、影や映り込みの少ない照明を用意する。
4. `nvm use` でNode 22、`.venv` でPython 3.13の環境を選ぶ。

## 確認項目

- カメラを列挙し、対象デバイスIDを選択できる。
- 接続後にフレームを継続取得できる。
- ROIがサイコロを振る領域だけを含み、保存後の再起動でも同じ比率で復元される。
- 「振る → 静止 → 候補 → 一度だけ確定 → 除去待ち → 次を受付」の順に遷移する。
- 同じサイコロを置いたままにしても二度確定しない。
- サイコロの除去、または明確な再移動で次の受付へ進む。
- 低信頼度では自動確定せず、管理者が承認または1〜6へ修正できる。
- USBケーブルを抜くと切断状態になり、再接続後は待機状態から安全に再開する。
- 認識タイムアウト後に手動入力できる。

## 記録する評価値

- 正解した投擲数 / 全投擲数（認識率）
- 誤った値を確定した数 / 確定数（誤確定率）
- 投擲開始から確定までの時間
- 照明、カメラ角度、距離、背景、使用したしきい値

映像や画像を通常ログへ含めない。評価用に保存する場合は、通常ログと分離した明示的な保存先を使い、参加者が映り込まない画角と研究計画に沿った削除・アクセス管理を確認する。

## 保存映像の評価

映像と同じ時間軸の正解ラベルをJSONで用意する。時刻は秒で、投擲区間同士を重複させない。

```json
{
  "rolls": [
    {
      "id": "roll-001",
      "expectedValue": 4,
      "startSeconds": 1.2,
      "endSeconds": 3.8
    }
  ]
}
```

次のコマンドで評価し、標準出力または `--output` でJSONレポートを得る。

```bash
.venv/bin/python -m commentator.services.vision.evaluation \
  study-video.mp4 study-video.labels.json \
  --settings var/vision-settings.json \
  --config var/recognition-config.json \
  --output var/evaluations/study-video.report.json
```

`--settings`と`--config`は省略できる。`--settings`は保存済みのカメラID、ROI、白領域しきい値、`--config`は次のような認識条件を適用する。省略したキーには既定値を使う。

```json
{
  "movementThreshold": 0.08,
  "stationaryThreshold": 0.02,
  "stationaryFrames": 10,
  "consecutiveValueFrames": 3,
  "candidateWindowFrames": 5,
  "removalFrames": 3,
  "automaticThreshold": 0.85,
  "confirmationThreshold": 0.60,
  "recognitionTimeoutSeconds": 10.0
}
```

レポートには次を含む。

- 最初の判断が正しい自動確定または確認候補だった投擲の割合（認識率）
- 誤った自動確定と投擲区間外の自動確定の割合（誤確定率）
- 投擲開始から最初の正しい判断までの平均・中央値・95パーセンタイル
- 投擲ごとの最初の判断、正誤、確認待ちの有無、確定時間
- しきい値未満で破棄した候補と、その信頼度内訳
- 判断ごとの総合信頼度と4つの内訳
- 認識設定、ROI、FPS、総フレーム数、映像時間、評価日時（UTC）

評価ツールは映像を読み取るだけで、映像やフレームを通常ログまたはレポートへ埋め込まない。

## 初回実機評価の条件

- 所要時間: 45〜60分
- 投擲回数: 最初に接続・ROI・切断復旧を確認した後、評価用に60回。各面が極端に少ない場合は、各面が最低5回になるまで追加する。
- 保存先: `recordings/dice-evaluation/YYYYMMDD/`。このディレクトリはGit管理対象外である。
- 画角: サイコロと黒い背景だけを基本とし、顔、名札、画面、書類などの個人情報を映さない。手が入る条件は重複防止と除去判定の確認に必要な範囲だけにする。
- 正解ラベル: 各投擲の開始・終了時刻と実際の出目を、映像と同じ時間軸で記録する。

## 2026-11-13 実機スモークテスト

- USBの `FHD Camera` をOpenCV ID 0、1920×1080で使用した。実測取得速度は約10 FPSだった。
- ROIはトレーだけを含む `x=0.34, y=0.06, width=0.34, height=0.54` とした。
- 黒いトレーの反射により大津の二値化は白領域を過大結合した。固定しきい値220では、トレー縁に接した出目3を75フレーム連続で検出できた。
- 既定の静止判定を3フレームから10フレームへ変更した。約10 FPSでは1秒、30 FPSでは約0.33秒の静止を待つ。
- 保存映像の再生で `waiting → moving → stationary → confirmed(3) → removal_wait → waiting` を確認し、総合信頼度は0.926だった。
- これは1投擲の通し確認であり、60投擲の認識率・誤確定率評価は未実施である。

## 2026-11-13 実機60投擲評価

- 60投擲中、最初の判断で正しく認識したのは45件（75.0%）、正しい自動確定は44件（73.3%）だった。
- 自動確定46件中2件が誤りで、誤自動確定率は4.35%だった。6を3、4を2として確定しており、斜め姿勢と白飛びで一部の目だけを数えた。
- 管理者確認候補は2件で、正解1件、誤り1件だった。余分な投擲区間外判断は0件だった。
- 面別認識数は1が9/12、2が7/8、3が9/11、4が7/10、5が8/9、6が5/10。6が最も不安定だった。
- 各フレームの単調増加時刻で測った確定時間は、平均1.839秒、中央値1.815秒、95パーセンタイル2.123秒だった。
- データとレポートは `recordings/dice-evaluation/20261113/sixty-rolls-20261113-174448.*` に保存した。映像、正解ラベル、フレーム時刻、評価レポートはGit管理対象外である。
